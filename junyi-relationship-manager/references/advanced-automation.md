## 启用条件

只有用户明确要求“接入飞书”“开启双写”“启用每周提醒”或“启用自动月报”时才执行。基础本地记录、手动跟进查询和手动关系报告都不依赖飞书。

开始前检查：

- 当前 Agent 能读取和写入飞书多维表格；
- 用户身份对目标 Base 有权限；
- 本地人物图谱路径已经明确且通过隐私检查；
- 用户明确授权创建或修改飞书表结构；
- 需要主动提醒时，当前 Agent 还具备定时任务能力。

缺少任一能力时说明缺口并保留本地模式，不生成虚假的 token、table_id 或成功回执。

## 配置结构

验证成功后才在用户指定的 `TOOLS.md` 写入非密钥配置：

```text
人物图谱路径: <用户确认的私人目录>/人物图谱/
关系图谱 app_token: <飞书 Base app_token>
关系图谱 people_table_id: <人物表 table_id>
关系图谱 interactions_table_id: <互动表 table_id>
关系图谱 followups_table_id: <跟进表 table_id>
关系图谱 automation_status: disabled | weekly | weekly_and_monthly
```

`app_token` 和 `table_id` 用于定位资源，不等于登录授权。不得把 app secret、access token、refresh token、密码、Cookie 或其他凭证写入 `TOOLS.md`、人物档案或 Git 仓库。

## 三表模型

### 人物表 `People`

稳定身份和当前状态，一人一行，主键为 `人物ID`。

| 字段 | 类型 | 说明 |
|---|---|---|
| 人物ID | Text 主键 | 与本地 `person_id` 一致 |
| 姓名 | Text | 展示名，不作主键 |
| 身份标识 | Text | 用于同名消歧 |
| 圈层 | SingleSelect | 家人/朋友/客户/外圈/待确认 |
| 关系类别 | Text | 只记录用户事实 |
| 亲密度 | Number | 1—5；未知留空 |
| 关系阶段 | SingleSelect | 认识/熟悉/信任/深度/核心/待确认 |
| 阶段来源 | Text | `user_fact` 或允许的系统规则 |
| 当前需求 | Text | 当前 active/paused 需求摘要 |
| 需求状态 | SingleSelect | active/paused/closed/unknown |
| 能提供的资源 | Text | 只记录明确表达 |
| 生日原文 | Text | 允许没有年份 |
| 最近互动时间 | Date | 从互动表同步 |
| 本地档案相对路径 | Text | 不写用户主目录绝对路径 |
| 最近更新 | DateTime | 系统计算 |

### 互动表 `Interactions`

只追加，一次交流一行。

| 字段 | 类型 | 说明 |
|---|---|---|
| 互动ID | Text 主键 | `interaction_YYYYMMDD_8位ID` |
| 人物ID | Text/Relation | 关联人物表 |
| 发生时间 | DateTime | 可为空 |
| 日期原文 | Text | 如“今天”“上周三” |
| 用户原始表达 | LongText | 用户输入或明确转述 |
| 结构化摘要 | LongText | 标记为系统提取 |
| 话题 | MultiSelect | 只做规范化索引 |
| 需求变化 | LongText | 新增、暂停、关闭或未知 |
| 阶段变化 | Text | 仅用户确认后记录 |
| 记录时间 | DateTime | 系统计算 |

### 跟进表 `Followups`

每个承诺或提醒一行，保留状态历史。

| 字段 | 类型 | 说明 |
|---|---|---|
| 跟进ID | Text 主键 | `followup_YYYYMMDD_8位ID` |
| 人物ID | Text/Relation | 关联人物表 |
| 承诺原文 | LongText | 用户真实承诺或明确提醒事项 |
| 到期时间 | DateTime | 未确定时留空 |
| 日期原文 | Text | 保留相对日期表达 |
| 日期来源 | SingleSelect | user_fact/system_computed |
| 状态 | SingleSelect | open/completed/cancelled/unknown |
| 完成时间 | DateTime | 只有明确完成后填写 |
| 跟进原因 | Text | 基于原话的简要说明 |
| 最后更新 | DateTime | 系统计算 |

月报所需的历史只能来自互动表和跟进表，不能用人物表的当前值反推历史。

## 启用流程

1. 读取现有配置和目标 Base；不要假设表不存在。
2. 列出现有三张表及字段，与上述模型比较。
3. 缺表时创建，缺字段时只新增缺失字段；遇到同名但类型冲突的字段时停止并说明，不能覆盖或重建用户数据。
4. 检查 `人物ID`、`互动ID`、`跟进ID` 的唯一性和关联字段。
5. 通过字段读取验证三张表都可访问。
6. 使用用户本次明确要求记录的真实人物完成第一笔双写；不要创建随后又要删除的虚构测试联系人。
7. 本地和飞书都成功后才写入配置并报告“双写已启用”。
8. 如果本次只配置、不记录人物，完成表结构读取验证后报告“结构已就绪，尚未验证真实记录双写”，不能说完全启用。

## 双写事务

一次记录按以下顺序执行：

1. 读取本地档案和飞书人物记录，按 `person_id` 确认身份。
2. 准备本地更新、人物表更新、互动表新增和跟进表新增/更新的预期内容。
3. 先追加互动与跟进记录，再更新人物表当前状态，最后写本地档案。
4. 逐项记录成功或失败，不重复创建已经成功的互动或跟进 ID。
5. 全部成功才回执“双写成功”。
6. 部分成功时明确列出成功位置、失败位置和安全重试方法；不得把部分成功说成完成。

重试时使用同一批次预生成的 ID，避免重复互动和跟进记录。

## 提醒与月报

### 每周提醒

只扫描跟进表：

- 已逾期且 `status=open`；
- 未来 7 天到期且 `status=open`；
- 日期为空但存在明确承诺的项目。

关系阶段节奏只能形成“建议关注”，不能自动生成用户承诺或更改跟进状态。

### 月报

允许计算：

- 本月新增人物：人物表创建时间在本月；
- 本月互动数：互动表发生时间或记录时间在本月；
- 跟进执行率：本月到期且状态可判断的跟进中，`completed / (completed + open逾期 + cancelled)`；同时分别列出取消数，避免掩盖；
- 需求闭环数：互动表中本月明确从 `active/paused` 变为 `closed` 的需求变化；
- 撮合建议数：只有另有明确撮合日志时才能计算；没有日志就写“未记录”。

亲密度趋势只有存在用户确认的历史变化时才计算。不得用互动次数推断亲密度上升。

### 定时任务

只有用户明确要求后才创建。任务提示必须包含：

- 读取哪些表；
- 只读扫描还是允许写报告；
- 输出发送到哪里；
- 不自动联系人物、不自动撮合；
- 遇到权限或字段错误时停止并通知用户。

创建完成后读取任务状态验证；仅凭生成了一段 cron 文本不能说任务已启用。

## 失败与降级

- 飞书不可用：继续本地记录，并明确“本地成功、飞书未写入”。
- 本地路径不可写：不改写飞书以制造单边成功；先解决本地路径。
- 表字段冲突：停止结构修改，输出冲突字段、现有类型和期望类型。
- 单次部分写入：保留批次 ID，按失败步骤重试，不从头新增记录。
- 定时任务不可用：提供手动查询方式，不宣称会主动提醒。
- 用户撤销飞书：停止外部写入并将配置状态改为 `disabled`；不擅自删除既有飞书数据。
