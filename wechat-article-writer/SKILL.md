# 微信公众号长文协作

这是唯一的公众号文章执行主体。Skill 保存通用流程、输入输出与门禁；每位作者自己的定位、语料、路径、授权、范本和发布规则只留在其私人工作区。

## 启动

1. 判断本轮状态：初始化、素材到大纲、从零成稿、续写、多轮改稿、终审、标题检查或配图规划。
2. 如果上游总编或编排器已经提供内容锁定单、类型判断与范本选择，直接承接，不另起一套公众号逻辑；没有上游交接时，本 Skill 自行完成这些步骤。
3. 只读取本轮明确授权的材料、工作区规则和作者配置。按 [配置契约](references/configuration-contract.md) 检查最小配置，精确读取 1–2 篇本轮指定的同类型授权全文范本；指定范本定位不到时报告缺失，不用其他文章替代。
4. 缺少最小配置或至少一篇授权全文范本时进入初始化模式：只交付配置缺口、素材盘点和可选大纲，不写个性化完整正文。
5. 根据已确认状态从对应阶段继续，不机械重跑已经完成的步骤。配置若指定了与本轮问题直接相关的授权复盘，可按需读取；没有就不用猜测或搜索。

用户可见交付只显示安全文档名或来源标签，不回显绝对路径、用户目录、隐藏目录、临时目录和仓库位置。

## 执行优先级

本轮明确要求与授权 > 当前工作区规则 > 作者配置与授权范本 > 通用写作建议。

事实、隐私、状态、CTA 与授权是硬门；字数、画面感、情绪浓度和传播建议不能覆盖硬门。授权范本只校准句长、停顿、叙事距离、情绪温度、具体颗粒度、留白和收尾方式，不迁移其中的事实、观点、心理、比喻、金句、CTA 或内容性短语。

按任务读取：

- 事实、隐私与发布状态：[证据与隐私](references/evidence-and-privacy.md)
- 人群、因果与判断范围：[论断范围](references/claim-scope.md)
- 长文结构、多轮改稿与标题：[公众号长文与改稿](references/wechat-long-form-editing.md)

## 公众号流程

### 0. 起心动念与传播任务

用一句话回答：为什么现在写、最想让谁读、希望对方读完理解什么或采取什么行动。区分拉新、建立信任和转化，不用渠道目的替代内容类型。

### 1. 角度与内容类型

从 2–3 个有材料支撑的角度中明确推荐一个，不把多个角度拼成一篇。用七类型判断主类型与最多一个辅类型：工具、角度、余韵、系统、人物、专论、实录。

反共识必须由事实或真实经历支撑；没有信息增量的唱反调不成立。没有范围证据时，角度型文章只提供一个新区分，不声称修正“常见看法”。

### 2. 素材盘点与内容锁定

建立或读取内容锁定单，逐项盘点：

- 写作目的、目标读者、主类型和核心判断；
- 原始记录与安全来源标签；
- 事实、数字、原话和时间线；
- 作者已经表达的判断及其强度；
- 核心金句及证据状态；
- CTA、发布状态、不可公开项和隐私边界；
- 仍缺的关键材料。

事实、作者判断、推断、待确认和不可公开项分开。没有支撑的内容直接不用或标 `[待补]`，不编场景、反应、对话、数据、观点、因果或适用范围。内容锁定单服务文章判断，不把风险字段写成正文主体。

### 3. 深度对话

只有主题、缺少个人体验或关键判断时，才问最少且真正阻断下一阶段的问题，例如：

1. 你真正经历了什么？
2. 哪个具体瞬间改变了你的判断？
3. 你现在最想保留的原话是什么？
4. 这个判断适用于谁，不适用于谁？

问题最多 3 个，可以为 0。目标读者、CTA、原话授权或状态已经确认时不重复询问；不为凑数索要身体感、戏剧场景、生活比喻或新案例。用户口述的顺序是信息源，不自动成为文章结构。

### 4. 大纲确认

成稿前给出：

- 一句话核心判断，注明来源与证据强度；
- 主类型与最多一个辅类型；
- 明确推荐的公众号骨架；
- 3–5 节大纲；
- 每节只负责什么、使用什么证据、怎样推进下一节；
- 开头入口和结尾方向；
- 标题候选与兑现位置；
- 真正阻断成稿的待补项和隐私风险。

先把推荐角度、核心判断与结构讲清，再附精简锁定信息；不要让表格和合规字段淹没文章主线。作者已经提供或确认完整大纲时可直接进入初稿，否则大纲未确认不写完整正文，除非作者明确要求跳过。

### 5. 选择公众号骨架

先按七类型，再让骨架服从本次材料：

| 主类型 | 常用骨架 |
|---|---|
| 工具 | 问题—方案—演示—边界 |
| 角度 | 真实矛盾—新判断—证据—适用范围 |
| 余韵 | 具体入口—体验展开—变化—开放收束 |
| 系统 | 真实问题—判断递进—方法关系—边界 |
| 人物 | 冲突—选择—代价—变化 |
| 专论 | 界定—主张—证据—反例—边界 |
| 实录 | 起点—节点—决策—状态—复盘 |

### 6. 初稿

- 用本次材料中的具体场景、动作和证据承载判断，不堆抽象概念；
- 一段只完成一个推进，下一段从上一段自然长出来；
- 结构服从内容，不搬运范本句子、观点或比喻；
- 保留作者真实原话的生命力，去掉 AI 式总结、对仗堆叠和过度升华；
- 涉及人物时只写有来源且允许公开的内容，不代写他人内心；
- 涉及工具、方法或结果时同时写适用条件、失败处和边界；
- 术语第一次出现先说人话，必要时括号补技术名，后文继续说人话；
- 材料不足时宁可短或留 `[待补]`，不用范本、常识和合理想象凑字数。

### 7. 多轮改稿

已有草稿或连续反馈时，先建立内部“改稿状态卡”，不要立刻逐句润色：

```text
标题承诺：
人物主线：
事件 / 机制线：
读者最终能带走的判断或动作：
每一节只负责什么：
当前最致命的问题：
本轮只解决什么：
```

按以下顺序修改：

1. 先修主角、核心冲突和章节边界，再修句子；
2. 检查每一节是否只完成一个任务，下一节是否由上一节自然长出来；
3. 标题中的身份、重大事件、时间、结果和反转必须逐项有正文场景；
4. 抽象总结继续追问“具体发生了什么”“读者下次可以怎样判断”；
5. 当系统、工具或技术线过强时，检查它有没有压过人物变化；
6. 当全文只有止损、补救和疗愈时，检查是否有真实证据支持正向创造价值；没有证据不硬补；
7. 情绪高潮后先让认知落稳，再进入方法、产品、课程、Skill、开源或网站；
8. 术语首次用白话说明，括号补技术名，后文继续说人话；
9. CTA 先回答读者能获得什么、第一步做什么，不用资产清单代替行动理由；
10. 每轮只处理 1–3 个最高优先问题，修改后重读相邻段落、整节和全文。

局部改写不等于只诊断局部。可以指出全文中真正影响标题承诺和人物主线的问题，但只改作者指定的文字范围；其余结构决定列为待判断，不擅自整篇重写。

当标题承诺、人物主线、读者价值和隐私边界都通过，剩余问题只属于配图、落地页或发布验证时，停止继续重写正文。

### 8. 事实与对抗审查

逐段核查：

- 事实、数字、原话、时间点能否回到本次材料；
- 判断强度有没有从个人经验被拔高为普遍因果；
- 标题、开头、小标题和结尾是否被正文兑现；
- 陌生读者能否复述“发生了什么、它怎样起作用、自己能带走什么”；
- 有没有漏掉反例、条件、失败或真正的代价；
- 人物、家庭、客户与业务隐私是否越界；
- 主角、核心判断和起心动念是否中途漂移；
- 系统、工具或技术线是否压过真正的人物和问题；
- 情绪高潮后是否先让判断落稳，再进入方法、产品或 CTA；
- 是否从授权范本迁移了内容，而不是只校准语感。

硬门失败时定向退回对应段落，不整篇无差别重写。

第一人称事实锁定改稿、含私人材料／候选状态／人群范围的大纲、以及使用授权范本完成的完整正文，展示前必须经过独立第二遍事实审稿。第二遍只拿“原始材料 + 本轮要求 + 第一遍草稿”检查新增事实、心理、时间、因果、范围、隐私、CTA、状态、范本污染和无效提问；保持第一遍的编辑判断与手感，只做最小删除、收窄或退回，不重新发挥。

环境支持独立只读审稿上下文时使用独立上下文；只能自审时，先完成草稿但不展示，再重新读取来源逐句检查。没有完成第二遍时只能标“待事实审稿”，不能写“通过”。

环境允许时运行：

```bash
python3 scripts/check_output_guards.py <draft.md> --scope-evidence none --status candidate --cta none
```

参数按本轮材料调整。脚本通过不替代人工逐句回读。

### 9. 语感打磨

对照本轮指定的 1–2 篇授权全文范本，只校准：

- 句长和停顿；
- 叙事距离；
- 情绪温度；
- 具体颗粒度；
- 常用与禁用表达；
- 留白和收尾方式。

当前原稿和作者本轮表达优先于风格摘要；风格摘要优先于外部文章。校准后做范本污染检查：若能指出某个观点、比喻、事件、心理、CTA 或内容性短语来自范本，而本次材料没有独立来源，就删除。

### 10. 标题、配图、排版与交接

标题确定后逐项列出承诺与正文兑现位置，并复查内容锁定差异。标题中的数字、时长、动作、心理、程度和状态都必须有材料来源。

配图先判断承担生活真实感、理解效率还是公开证据：

- 真实经历优先使用已授权照片、原始记录或真实界面；
- AI 图片不得冒充生活现场、人物、聊天、软件界面或运行证据；
- 截图只保留支撑正文的最小区域，检查路径、凭据、账号、学校、客户和私人文件名；
- 不为每个故事机械配图，不在情绪高潮中插入产品图或技术图；
- 每张图说明用途、插入位置、来源和授权状态。

CTA 必须来自作者配置或本轮明确确认。未经确认不添加价格、名额、效果承诺、评论区、私信、联系方式或软性邀请。本 Skill 不自动发布。

### 11. 发布后的证据回写

只有作者明确确认已发布，或提供平台原文链接／后台回读证据时才执行。草稿、预览、排版完成和待发布计划都不算发布。

最低发布证据包括：实际平台、发布时间、公开链接或等效后台证据、最终稿版本。回写前展示目标和拟写内容并取得授权；缺证据时只标“待回写”，不把候选写成已发布。

## 事实锁定编辑

当作者要求“不增加新事实”时，待改原文是唯一事实词典，并覆盖写作 DNA、授权范本、默认 CTA、目标长度和通用“增强画面”建议。

默认允许轻度转述、拆合句、删减和重排，但不能改变或新增人物、动作、对象、程度、时间、动机、情绪、判断、因果、比喻和 CTA。明确要求“抽取式／只删改重排／逐字保留”时，才进入严格抽取模式。

重点拦截隐蔽新增：原文没有时，不写“我停了一下、我原以为、没想到、后来才发现、第一次意识到、反复想过、终于明白、差点、用了几年”等心理、动作、时间和程度桥接。相邻两段不自动构成因果或转折。

诊断层可以依据原文提出清楚的编辑判断，但不能把判断改写成正文里的新经历、新心理或新因果。原文没有 CTA 且本轮未授权新增时，正文、诊断、建议和备选方案都不引入 CTA，终审写“不适用”。

## 展示前硬门

先在内部审查并删除不合格候选，再输出。禁止：

- 写进无来源句子，再问作者“是否越界”；
- 展示含无来源数字、时间或心理的标题，再备注“确认后可用”；
- 使用“常见看法、所有人、创作者通常、共同焦虑、读者会代入、共鸣最强／最宽、最快、一定”等无证据范围或最高级；
- 把“担心、不放心、怎么办”等情绪词误称为身体感；
- 为凑满数量而询问场景、体感、比喻或已经确认的读者、CTA 与状态。

如果一句话需要作者补证，它不得出现在候选正文、开头、标题或 CTA 中；只在确实阻断下一阶段时列一个最小问题。

## 输出

按任务交付最小完整结果：

- 初始化：配置缺口、素材盘点、可选大纲和下一步，不输出完整正文；
- 大纲：内容锁定单、主类型／辅类型、2–3 个合格角度及明确推荐、核心判断、3–5 节大纲、开头结尾、标题兑现、风险与必要问题；
- 正文：已确认大纲、标题候选、正文、事实／待确认／不可公开、锁定差异和发布前最小验证；
- 多轮改稿：改稿状态卡、1–3 个最高影响问题、本轮修改结果、五项终审、具体改动和仍需作者判断的结构问题；
- 终审：逐项门禁、阻断项和最小修复；未经要求不重写全文。

如果作者只要大纲、局部改稿或标题，只交付对应范围，不强制输出全文。输出顺序首先服务阅读与判断，再放合规附录；不要让过程说明、风险表格或自我声明盖过真正的编辑结果。

## 边界

- 只服务微信公众号长文，不承担朋友圈、小红书、视频脚本或其他平台；
- 不声称模型生成文字是作者原话，不复制授权范本中的独特表达或私人事实；
- 不编造效果、收入、家庭、客户、健康、教育或业务案例；
- 不因追求传播扩大判断、制造焦虑或泄露隐私；
- 不把配置、范本和材料复制进公开 Skill、示例、日志或反馈表；
- 未经授权不修改素材、配置、知识库、台账或平台数据，不发布、不发送。
