# 蒸馏规则（三类候选 + 三段式 + 汇周去重印证）

> 本文件是 ai-weekly-review 蒸馏层的方法论。纯方法，与数据来源无关。
> 节奏：**先逐日蒸馏（保颗粒度），再汇周（去重 + 印证）**。

## 一、节奏：先分日，后汇周

- **不要把 7 天揉成一坨蒸馏**（量大 → 模型抓大放小 → 金句 / 灵光被碾过）。
- **按天逐日蒸馏**：对 `days/<date>/` 每天的 chunk 单独蒸馏，7 天 = 7 次，每次只面对一天。
- **再汇周**：7 份日级结果合并 → 去重 + 印证 → 出两份周度产出。
- 代价：慢一点（循环 7 次）。一周一次，可接受。

## 二、每日抽三类候选

### A. 方法工作流（三段式，每条必须齐）

- **标题**：一句大白话讲清这个做法，不用大词。
  （好例：「别人给你一套格式前，先看自己后面够不够用」）
- **发生了什么**：什么场景 → 谁 → 做了什么动作 的动作链，让人对得上号。
- **方法要领**：以后遇到类似情况照着怎么做，口语化。
  🔴 **禁止堆抽象词 / 大词**。写成「以后别人给你一套格式让你照着用之前，先看看你后面那步流程缺不缺东西」这种话，不要写「比对下游流程必需字段」。
- **下一步**：要不要固化？固化到哪（可选，但有就写）。

### B. 判断原则

- 用户稳定的取舍（不是单次情绪），能回答「以后类似情况怎么判断」。
- 一段叙述即可，不用三段式。

### C. 工具 / 想法候选

- 重复 ≥2 次、或单次但高复杂度可自动化的事。
- 带「下一步」（可以做成什么、固化到哪）。

## 三、共同要求

- **少即是多，宁缺毋滥，不做流水账**。改字 / 跑命令 / 确认收到 这类执行流水**直接跳过**。
- **每条带证据回指**：record_id 前 8 位 / chunk 号 / 日期，至少一个，让人能回去查原文。
- 🔴 **真实性铁律**：每条都必须有原始出处。看不清 / 拿不准的标 `[此处不确定]`，**宁缺毋假**，禁止脑补杜撰。

## 四、汇周去重 + 印证（关键，防逐日重复）

7 份日报合并时：

1. 同一条判断 / 方法在多天反复出现 → **不重复列**，合并成一条，标「本周印证 N 次」。
2. **印证次数 = 信号**：出现越多越值得固化，在周报里**置顶 / 高亮**。
3. 单次出现 → 正常列入「本周新增」。

## 五、多 agent 工作日志（按需）

- 数据源同抓取层，但这里**保留工作动作**（不像对话沉淀只留 user/assistant 文本）。
- 从各 agent 的 session 提取：这周做了哪些任务 / 产出了什么 / 有没有卡点。
- 看 `manifest.md` 的「各 agent 记录数」：
  - **>1 个 agent** → 出「各 agent 本周工作」一节。
  - **只有 1 个 agent** → 优雅降级，**自动省略本节**，不搭空架子。
