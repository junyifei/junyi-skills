# 两份产出模板

> 排版规范：标题用中文序号或清晰 Markdown，不堆 `━━━`；🔴 禁用破折号（——），用逗号 / 句号 / 括号；引号用「」或 “ ”。
> 🔴 每一条都要有原始出处（record_id 前 8 位 / chunk 号 / 日期）。拿不准标 `[此处不确定]`，宁缺毋假。

---

## 8.1 《本周记录》（给用户本人）

文件名建议：`本周记录_YYYY-Wxx.md`

```markdown
# 本周记录 YYYY-Wxx (YYYY-MM-DD ~ YYYY-MM-DD)

## 一、本周概览
（3 到 5 句：这周和 AI 主要在做什么，整体节奏）

## 二、各 agent 本周工作   ← 只有 1 个 agent 的用户自动省略本节
- <agent A>：完成 X / 产出 Y / 卡点 Z
- <agent B>：...

## 三、本周方法工作流（去重后）
（三段式条目：标题 / 发生了什么 / 方法要领 / 下一步。「本周印证 N 次」的置顶）
1. **<标题>**　（印证 N 次）
   - 发生了什么：...
   - 方法要领：...
   - 下一步：...
   - 出处：rec 1a2b3c4d / chunk_007 / 06-23

## 四、本周判断原则（去重后）
- <一句原则>。（以后类似怎么判断：...）　出处：...

## 五、本周工具 / 想法候选
- <想法>：重复 N 次 / 可自动化。下一步：...　出处：...

## 六、来源索引
- 扫描范围：YYYY-MM-DD ~ YYYY-MM-DD（本地时区）
- 数据源与记录数：Claude Code N 条 / OpenClaw N 条 / Codex N 条 / ...
- 未支持来源：（如 Hermes / WorkBuddy 本机未探测到，如实写明）
```

## 8.2 《本周内容素材》（给内容创作）

文件名建议：`本周内容素材_YYYY-Wxx.md`

```markdown
# 本周内容素材 YYYY-Wxx

## 一、可写的故事
（这周发生的、有张力的真实片段，可做文章 / 帖子素材。带出处）

## 二、可分享的方法 / 心法
（从方法工作流里挑出适合对外讲的，转成读者听得懂的话）

## 三、选题线索

每条候选先做两步自检，再决定是否进入本节：

**自检 A：用户本人的位置**
- ⭐ 主角或亲历者：用户是故事当事人，有真实经历、行动和感受。
- ⚠️ 有独特观察但需找角度：用户在场或有直接观察，但不是故事主角。
- ❌ 旁观者或转述者：用户只是听说、见证或转述别人的故事。

**自检 B：观点新鲜度**
- ⭐ 反常识或独特框架：在目标读者的信息圈里较少被这样讲。
- ⚠️ 常识但讲法可独特：观点不新，但用户有自己的真实故事、反例或决定过程。
- ❌ 圈子常识且无独特讲法：底层主张已被反复表达，用户也没有独特证据。

筛选规则：只列双 ⭐，或至少一个 ⭐ 加一个 ⚠️ 的候选。出现 ❌ 的候选不作为选题，可降到「可写的故事」或「可分享的方法与心法」留存。每条末尾标注结果，例如「独特性：A⭐ B⚠️」，并保留出处。

（这里只列真正值得展开的选题，不为凑数量包装普通素材。）

## 四、金句捞取
（原样摘录用户 / AI 说过的有传播力的话，🔴 不转述、不改写，标出处）
> 「……」　出处：rec 1a2b3c4d / 06-24
```

## 空周报（empty-week）

窗口内无有效对话时，仍出两份文件，如实说明：

```markdown
# 本周记录 YYYY-Wxx
本周扫描范围 YYYY-MM-DD ~ YYYY-MM-DD 内，未发现有效 AI 对话记录。
扫描了：Claude Code / OpenClaw / Codex（命中 0 条）。未支持：Hermes / WorkBuddy（本机无存储）。
```
