# 长文结构与改稿方法

## 先选择推进方式

结构从材料中长出来。常见选择包括：

- **事件推进**：事件发生 → 当时判断 → 转折 → 现在理解 → 给读者的启发。
- **问题拆解**：真实问题 → 常见误读 → 证据与机制 → 可执行做法 → 边界。
- **案例时间线**：起点 → 连续的关键节点 → 决策变化 → 结果或未完成状态 → 复盘。
- **观点论证**：主张 → 证据 → 反例或限制 → 适用条件 → 结论。
- **观察随笔**：具体入口 → 多个相互支撑的观察 → 内在变化 → 开放式收束。

若材料不支持完整结论，宁可写成观察、问题或阶段性复盘，不制造成功闭环。

## 大纲检查

每一节都应回答一个清楚的问题：

- 这一节推进了什么？
- 使用了哪条材料？
- 它与主轴的关系是什么？
- 删除后文章是否损失必要信息？

连续两节承担同一功能时合并。案例放在它能证明的观点附近，不把所有故事堆在开头。

## 起草原则

- 优先保留原素材中准确、有辨识度的表达，不凭空补“更生动”的细节。
- 抽象观点后给一个可验证的事实、场景或推理过程。
- 段落一次推进一个意思；长短服务阅读节奏，不机械切成碎句。
- 过渡说明逻辑关系，不用空泛总结代替推理。
- 结尾完成文章的最后一步，可以是判断、行动、问题或邀请；不强行升华。

## 改稿顺序

按影响从大到小修改：

1. **主轴**：文章是否仍在回答原来的问题。
2. **结构**：章节顺序、案例位置、删减和缺口。
3. **证据**：事实、引语、因果、隐私和论断强度。
4. **段落**：每段的功能、连接与信息密度。
5. **句子**：语气、词汇、节奏和冗余。
6. **包装**：标题、小标题、摘要和行动邀请。

不要在主轴未稳定时反复润色句子。

## 处理修改反馈

当使用者说“偏了”“不像我”“没看懂”或指出某个故事不成立时：

1. 复述具体偏差，不用泛泛道歉代替判断；
2. 回到原素材、原主轴和本轮修改目标；
3. 判断问题属于主轴、结构、证据还是表达；
4. 先给局部修复方案，得到的信息足够时直接修改；
5. 标明本轮改了什么，避免下一轮再次漂移。

## 标题与正文

标题中的对象、冲突、变化和收益都必须能在正文中找到对应内容。标题可以有张力，但不能把进行中写成完成、把个人经验写成普遍结论、把一次反馈写成稳定结果。

终审时逐项写出标题承诺，并标注正文兑现位置。没有兑现的承诺，应修改标题或补足有证据的正文，而不是增强修辞。
