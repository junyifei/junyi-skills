# 使用者配置契约

配置的作用是让同一个公开 Skill 适配不同创作者，而不是把某个人的私人资料复制进 Skill。

## 可读取的配置

使用者可以提供一个文件或若干文件，包含以下任意信息：

- **identity**：身份、长期主题、专业边界。
- **audience**：核心读者、读者处境、默认知识水平。
- **voice**：常用语气、段落节奏、偏好与禁用表达。
- **authorized_samples**：已获授权、可用于学习语感的本人完整范文。
- **content_rules**：选题边界、事实标准、隐私红线。
- **publishing_rules**：平台、标题要求、结尾方式、行动邀请和发布前检查。
- **source_locations**：本次允许读取的素材目录或文件；必须由使用者或工作区规则明确提供。

配置不要求固定格式。结构化文件可以使用上述字段；普通 Markdown 也可以，只要含义明确。

## 读取顺序

1. 本次对话中的明确要求；
2. 本次任务指定的配置与素材；
3. 工作区内已明确生效的规则；
4. 授权范本中可归纳的稳定语感。

低层级内容与高层级冲突时，不要自行折中。按高层级执行，并说明被忽略的冲突项。

## 没有配置时

进入中性模式：

- 从使用者当前输入学习词汇和节奏；
- 不宣称已掌握其个人定位或写作风格；
- 不扫描其他目录寻找个人资料；
- 能完成的部分先完成，只列出会显著影响结果的缺口；
- 若使用者希望长期复用，再建议其建立最小配置：身份、读者、语气、一个授权范本、隐私红线。

## 安全边界

- 配置只在当前授权范围内使用，不复制进公开 Skill、示例或日志。
- 不因配置中出现文件路径，就扩大到整座知识库搜索。
- 不修改配置或范本，除非使用者明确要求。
- 范本只能用于提取抽象语感和结构偏好，不能搬运其中的私人事实、独特句子或未授权案例。
